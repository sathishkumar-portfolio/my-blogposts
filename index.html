Wafer Tracking API

The Wafer Tracking API enables real-time monitoring of wafer movement, process states, and system-level events across semiconductor manufacturing workflows.

Designed for integration with MES platforms, equipment monitoring systems, and engineering dashboards.

Base URL

https://api.wafertrack.com/v1

Authentication

All requests require an API key, passed as a bearer token in the Authorization header.

Authorization: Bearer YOUR_API_KEY

Example Request

curl -X GET "https://api.wafertrack.com/v1/wafers/WF10293" \
  -H "Authorization: Bearer YOUR_API_KEY"

Get Wafer Details

Returns the current status, location, and priority of a single wafer.

Endpoint

GET/wafers/{id}

Sample Request

GET /wafers/WF10293

Sample Response

{
  "waferId": "WF10293",
  "status": "Processing",
  "location": "EUV Station 04",
  "priority": "high",
  "updatedAt": "2026-05-01T11:32:00Z"
}

Get Workflow History

Returns the ordered sequence of module events for a wafer, useful for audit trails.

Endpoint

GET/wafers/{id}/history

Sample Response

[
  {
    "module": "Load Port",
    "event": "entered",
    "timestamp": "2026-05-01T08:00:00Z"
  },
  {
    "module": "Lithography",
    "event": "processing_started",

  },
  {
    "module": "Inspection",
    "event": "completed",

  }
]

Update Wafer Status

Updates the current status and module assignment of a wafer.

Endpoint

POST/wafers/{id}/status

Request Body

{
  "status": "completed",
  "module": "Inspection",
  "operatorId": "OP-204"
}

Response

{
  "message": "Status updated successfully"
}

Get Active Wafers

Returns all wafers currently in a processing state.

Endpoint

GET/wafers?status=processing

Sample Response

[
  {
    "waferId": "WF10021",
    "module": "Lithography"
  },
  {
    "waferId": "WF10044",
    "module": "Inspection"
  }
]

Error Handling

All errors follow a standardized structure.

{
  "error": "Wafer not found",
  "code": 404,
  "requestId": "req_92KlmX"
}
CodeDescription
200Successful Request
400Invalid Request
401Unauthorized
404Wafer Not Found
429Rate Limit Exceeded
500Internal Server Error

System Constraints

  • Data synchronization may experience 2–5 second delays
  • Duplicate events may occur during retry operations
  • System uses eventual consistency architecture
  • Event ordering depends on equipment clock synchronization
  • High-frequency polling may trigger request throttling

Best Practices

  • Cache frequently requested wafer data
  • Retry failed requests with exponential backoff
  • Validate wafer IDs before sending requests
  • Use workflow history endpoints for audit tracking
