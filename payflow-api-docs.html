PayFlow API
Developer Reference

PayFlow provides a unified REST API for payment initiation, settlement orchestration, refund management, and real-time event streaming across card, bank-transfer, and wallet payment rails.

BASE URL https://api.payflow.io/v2

All requests use HTTPS. HTTP requests are rejected with 301 Moved Permanently. JSON is the only supported content type for both requests and responses.

Productionhttps://api.payflow.io/v2
Sandboxhttps://sandbox.payflow.io/v2
Staginghttps://staging.payflow.io/v2
💡

Use the sandbox environment for all development and testing. Sandbox transactions are not processed by real payment networks and incur no charges.

Getting Started

Authentication

All API requests are authenticated using API keys. Include your key in the Authorization header of every request.

PayFlow issues two types of API keys. Use the appropriate key based on where your code runs:

  • Secret key (pf_live_sk_…) — for server-side use only. Never expose in client-side code or version control.
  • Publishable key (pf_live_pk_…) — for client-side SDKs and browser environments. Does not grant server-side access.
cURL Python Node.js 
curl -X GET "https://api.payflow.io/v2/payments/pay_9Kx3T" \
  -H "Authorization: Bearer pf_live_sk_aB3mNqZ7rP1xV0" \
  -H "Content-Type: application/json"
⚠️

Rotate your secret keys immediately if you suspect they have been compromised. Revoke keys in the PayFlow dashboard under Settings → API Keys.

Getting Started

Request Format

All request and response bodies use JSON. Set the appropriate headers on every request.

Required headers
HeaderValueDescription
AuthorizationBearer <key>Your API secret key
Content-Typeapplication/jsonRequired for POST and PATCH requests
Idempotency-Keystring (UUID)Optional. Prevents duplicate mutations on retries
PayFlow-Version2024-11-01Optional. Pin the API version for your integration
ℹ️

Use the Idempotency-Key header on all POST requests. If a network error occurs and you retry the request, PayFlow returns the original response instead of creating a duplicate resource.

Rate Limits

Rate limits are enforced per API key. Exceeding a limit returns a 429 Too Many Requests response.

Read endpoints (GET)1,000 req / min
Write endpoints (POST / PATCH)300 req / min
Delete endpoints60 req / min

Rate limit headers are returned on every response:

X-RateLimit-LimitTotal requests allowed in the current window
X-RateLimit-RemainingRequests remaining in the current window
X-RateLimit-ResetUnix timestamp when the window resets
Retry-AfterSeconds to wait before retrying (on 429 only)

currencystringrequiredThree-letter ISO 4217 currency code. E.g., INR, USD
payment_methodobjectrequiredPayment method details. See payment_method object below

List Payments

Returns a paginated list of payments. Results are ordered by creation date, most recent first.

GET /payments List all payments
Query parameters
ParameterTypeRequiredDescription
limitintegeroptionalNumber of results per page. Default: 20. Max: 100
cursorstringoptionalPagination cursor from a previous response's next_cursor field
statusstringoptionalFilter by status: pending, processing, succeeded, failed, cancelled
customer_idstringoptionalFilter payments for a specific customer
fromstring (ISO 8601)optionalStart of the date range filter
tostring (ISO 8601)optionalEnd of the date range filter
cURL
curl -G "https://api.payflow.io/v2/payments" \
  -H "Authorization: Bearer pf_live_sk_aB3mNqZ7rP1xV0" \
  -d status=succeeded \
  -d limit=5 \
  -d from=2024-11-01T00:00:00Z
200 OKPaginated list

Cancel a Payment

Cancels a payment that has not yet been captured. Only payments in pending or authorized status can be cancelled.

DEL /payments/{payment_id} Cancel a payment
Path parameters
ParameterTypeRequiredDescription
payment_idstringrequiredThe ID of the payment to cancel
cURL
curl -X DELETE "https://api.payflow.io/v2/payments/pay_9Kx3TrZmN8bW" \
  -H "Authorization: Bearer pf_live_sk_aB3mNqZ7rP1xV0"
200 OK
{ "id": "pay_9Kx3TrZmN8bW", "status": "cancelled" }
⚠️

Payments in succeeded status cannot be cancelled. Create a refund instead. See Create a Refund.

Webhooks

Register a Webhook Endpoint

Registers a URL to receive real-time event notifications. PayFlow sends a signed POST request to this URL when subscribed events occur.

POST /webhooks Register endpoint
Request body parameters
ParameterTypeRequiredDescription
urlstringrequiredHTTPS URL to receive event payloads
eventsarray[string]requiredList of events to subscribe to. Use * to subscribe to all events
descriptionstringoptionalHuman-readable label for this endpoint
Available event types
payment.succeededFired when a payment transitions to succeeded
payment.failedFired when a payment cannot be completed
payment.cancelledFired when a payment is cancelled
refund.createdFired when a refund is initiated
refund.succeededFired when a refund settles successfully
customer.createdFired when a new customer record is created
RequestResponse 200
POST /webhooks
{
  "url": "https://yourapp.io/webhooks/payflow",
  "events": ["payment.succeeded", "refund.created"],
  "description": "Production order fulfillment listener"
}
ℹ️

PayFlow signs all webhook payloads using HMAC-SHA256. Verify the PayFlow-Signature header before processing any event to prevent spoofed requests.

Pagination

All list endpoints use cursor-based pagination. This approach remains stable even when items are added or removed between requests.

To retrieve the next page of results, pass the next_cursor value from the previous response as the cursor query parameter on the next request. When has_more is false, you have reached the last page.

  • Default page size is 20 items
  • Maximum page size is 100 items
  • Cursors are opaque strings. Do not parse or store them beyond the current session
